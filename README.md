# urban-os · требования как данные

Интерпретация нормативных требований к получению **свидетельства об утверждении
архитектурно-градостроительного решения** (АГР) объекта капитального строительства
в городе Москве.

## Принцип

**Этот репозиторий не является источником права.** Источник — нормативные акты,
перечисленные в `sources/index.json`. Здесь лежит их *проверяемая транскрипция*:
каждое правило ссылается на пункт первоисточника (`sourceRef`), а каждый
первоисточник — на файл с его sha256.

При расхождении между правилом и первоисточником прав первоисточник, а правило —
дефект транскрипции и чинится выпуском новой версии профиля.

## Раскладка

```
sources/index.json           реестр нормативных источников и внешних органов
requirements/*.json          корпуса требований (профили), по одному на документ
tools/validate.py            проверка целостности реестра + прогон фикстур
tests/fixtures/*.json        золотые кейсы: контекст → ожидаемые counts
```

## Правила версионирования

1. **Опубликованный профиль не редактируется.** Исправление любой ошибки, включая
   опечатку, — это новый файл `.v2`. Иначе выданные ранее отчёты становятся
   неповторяемыми.
2. **`selfHash`** в профиле — sha256 его содержимого без самого поля. Считает и
   проверяет `tools/validate.py`.
3. **Проект пинится** на пару `{profileId, version}` и не переезжает на новую
   редакцию сам. Перевод — явное действие с показом дельты.
4. **`status`**: `draft` → `active` → `superseded`. Активной может быть одна
   версия профиля на юрисдикцию и класс модели.

## Типы верификации

| Тип | Кто закрывает | Пример |
|---|---|---|
| `automatic` | движок по `evaluator` | размер ZIP, число треугольников, синтаксис GeoJSON |
| `expert_evidence` | человек с доказательством | нормали наружу, UV без швов, соответствие проекту |
| `external_fact` | внешний документ со сроком | действующий ГПЗУ, выписка ЕГРН |
| `external_verdict` | другое ведомство | заключение Мосгорнаследия, Комитета по туризму |

`automatic` и `expert_evidence` дают терминальное состояние внутри контура.
`external_fact` и `external_verdict` — нет: их нельзя «закрыть экспертизой», можно
только получить или дождаться. В счётчике готовности они считаются отдельно.

## Статус правила `pending_activation`

Часть требований записана в регламенте, но ещё не действует — например,
соответствие результатам цифрового мастер-планирования применяется «после
утверждения алгоритмов в установленном порядке». Такие правила несут
`status: "pending_activation"` и `activationCondition`, не участвуют в подсчёте
терминальности и видны в реестре как предстоящие.

## Проверка

```bash
python3 tools/validate.py
```

Без зависимостей. Проверяет: ссылочную целостность `sourceId`, уникальность
`id`, соответствие `selfHash`, полноту обязательных полей, применимость
`evaluator` только к `automatic`, и прогоняет фикстуры из `tests/`.

Пересчитать хэши после правки черновика:

```bash
python3 tools/validate.py --rehash
```

## Что ещё не оцифровано

| Корпус | Почему важен |
|---|---|
| Требования к материалам в формате IFC | закрывает документы 4, 5, 7 комплекта — СПОЗУ, планы этажей, разрезы и фасады |
| XML-схема таблицы суммарной поэтажной площади | документ 8 комплекта |
| Приложение к Админрегламенту — состав материалов АГР | детализация документа 2 |

Первое приоритетнее остальных: несоответствие формату отсекается на приёме, то
есть до содержательного рассмотрения моделей.
